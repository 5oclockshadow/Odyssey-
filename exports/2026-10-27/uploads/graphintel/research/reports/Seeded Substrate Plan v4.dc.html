Headline experiment

Seed once. Shrink the model. Watch the line stay flat.

One Bridago brain, seeded once. The same tasks run on a ladder of substrates: 30B, 8B, 1–3B, a tiny transformer, an LSTM on a CPU. Unseeded, quality falls with size, as dspy-router-test already shows. Seeded, Anima predicts the curve flattens. The demo is the two curves on one chart.

The claim this tests: a large, expensive model is not required when the cognitive and memory layer is built right. That holds whether or not the infrastructure around it is a moat. What decides graph intelligence is the brain, and above all how it is seeded.

No prior work we found runs one seeded brain across this whole range of substrates. inferred

02 · Thesis

Stated so it can fail

T · the claim

On tasks whose difficulty is structural (deep schemas, multi-hop reachability, typed constraints), accuracy is governed by the seed and the cognition layer. Substrate size and architecture become second-order once the seed is present.

Three consequences follow, and each is measurable separately:

  • Gap closure. A seeded small model reaches a large model on the same task.
  • Substrate invariance. With the seed, the spread between substrates shrinks; without it, it does not.
  • Structure, not volume. A shuffled seed of the same size gives back almost none of the gain.
  • Seeding decides. Seed quality moves accuracy more than substrate size does.

04 · The LSTM argument

Why an LSTM on a CPU is the sharpest test

If the graph carries the cognition, the substrate only has to read the seed, follow the cognition layer's fields and emit. A recurrent network does that in constant memory per step and linear time, which is what makes CPU inference viable. It is also the substrate with the best-documented weakness, so a pass here means more than a pass on a small transformer.

For
  • xLSTM adds exponential gating and matrix memory and scales competitively with transformers and SSMs [7]; a 7B xLSTM targets fast, memory-flat inference [8].
  • minLSTM / minGRU drop the hidden-state dependency from the gates, train in parallel and match recent sequence models on several tasks [9].
  • Fixed state per step: cost does not grow with context, so a long seed costs once.
Against
  • Fixed-size state loses at associative recall; the gap explains most of the quality difference to attention [10].
  • RNNs cannot do in-context retrieval as transformers do; retrieval augmentation or one attention layer closes the gap [11].
  • Copying long strings from context favours transformers over fixed-state models [12].
Our reading inferred

The LSTM's known failure is recall from context. In this design the context is not where the structure lives: the graph is, and Bridago serves it as a lookup. The thesis therefore predicts a specific shape of result: the LSTM fails unseeded, fails seeded-in-context (the seed is just a long prompt it cannot recall from), and passes seeded-by-retrieval. Wen et al. already show retrieval closes the RNN gap on retrieval tasks [11]; v4 asks whether it also closes it on structural reasoning. If seeded-by-retrieval does not lift the LSTM, the cognition is not in the graph.

05 · Seed specification

One file, five blocks

Unchanged in content from v3 Part 7; v4 fixes the format so every codebase reads the same file.

seed.yaml
  version: 4
  incidence:   B  (n_nodes × n_hyperedges, sparse COO)
  types:       node → ontology symbol, symbol → parent
  restriction: hyperedge → node map (what a node may hold, how it must agree)
  constraints: transitivity, disjointness, cardinality (Horn clauses)
  energy:      consistency score; the halting rule for the round
  control:
    shuffle:   same degree sequence, permuted incidence  (S-shuf)
    delivery:  in_context | retrieval | destroyed

Generator lives in rex-graph-agent: seed gen --nodes 64..4096 --depth 1..6 --seed <int>. Every run records the generator seed so any row of the results table can be rebuilt.

06 · Cognition layer

The DSPy layer, fixed across substrates

  • One Signature, one input field, one output: intake → reframe → reasoning → preact → act → postact.
  • Reasoning-first field order, declared types and descriptions on every field (v3 Parts 13–14).
  • Two shapes: nested six-deep (current) and rank-split (three emissions), so depth is a factor and not a confound.
  • Optimiser: GEPA on the Phoenix trajectories, compiled once per substrate on a held-out split [13].
  • Halting: the seed's energy, max 8 refinements, as TRM's deep supervision [2].

10 · Phases

Order of work

  1. P0 · Unify. Rex and Jarvis merged as branches of Bridago, one port map, one repo under bridago/.
  2. P1 · Replicate. S∅ reproduces dspy-router-test. If it does not, stop and fix the baseline.
  3. P2 · Seed. Generator, shuffle control and Bridago retrieval, with tests.
  4. P3 · Small grid. L, S, R at depth 1–3, curated seed only. Read H0, H4, H5 before spending on the rest.
  5. P4 · Full grid. All rungs, depth 1–6, three seed qualities, probes.
  6. P5 · Publish. Report v4 and the headline demo: seeded vs unseeded curves from 30B to LSTM on one chart. Results on the public graph, raw runs on the private one.
11 · Risks

Ways the result could mislead

  • The retriever does the reasoning. If Bridago returns closures, the substrate is only copying. Log every lookup; report the share of answers that are a single retrieved fact.
  • L fails too. Deep schemas break large models [6]; "match L" then means little. Report absolute validity next to the gap.
  • Generated tasks are too clean. Add one real schema set from the institute graph before P5.
  • GEPA overfits per substrate. Compile on a split the grid never sees.
