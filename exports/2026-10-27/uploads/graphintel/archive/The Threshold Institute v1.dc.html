How it runs itself

Built on the research it publishes.

The Institute runs the construction from its own report on graph intelligence. Nothing is hard-coded: the file above is the company, this site is rendered from it, and the agent changes it only by pull request.

01 · SeedRead once, then destroyed

Each round starts from a formal seed: the graph's structure, its types and an energy. No prose instructions. After that the graph lives inside the round.

02 · RoundThink until the energy settles

The agent emits nodes, hyperedges and closure, repeats, and stops when its consistency energy stops falling. Hard questions get more rounds; easy ones fewer.

03 · LearnReflect, then file a pull request

Every round's trace is reflected on in language. Changes to prompts, skills or edges are accepted only if they lower the energy on held-out seeds.

Lifecycle of an app
  1. Request arrives from chat, the site, or a social surface.
  2. SEXTANT drafts a one-page spec and tests; posts it to the record.
  3. A human approves. Nothing is built without approval.
  4. Build in docker-in-docker; run lint, unit, integration, acceptance.
  5. On failure: trace → diagnose → patch → rerun. Up to five attempts, then park and report.
  6. Launch in its own container; health-checked; crash triggers step 5 again.

Test until pass · the loop every change runs
  1. Lint and types. Fails fast on anything malformed, including the YAML.
  2. Unit tests. The round's emission is checked against its own schema; every skill has its own tests.
  3. Integration in docker-in-docker. Tools, MCP servers and the served app are exercised end to end in a disposable container.
  4. Acceptance. The change must lower the consistency energy on held-out seeds, under an anytime-valid test, so the loop can stop early without inflating false positives.
  5. Pull request with the trace attached. Dependency fixes inside the boundary merge automatically; self-edits wait for a human.

On any failure: trace → diagnose → patch → rerun from step 1. Five attempts, then the change is parked and reported in the record. The gates themselves, CI and secrets are outside the agent's edit boundary.

      - run: make unit
      - run: make integration        # docker-in-docker
      - run: make acceptance         # energy on held-out seeds
      - if: failure()
        run: make park-and-report
