# Changelog

All notable changes to `selfwire` are recorded here. Versions follow
`MAJOR.MINOR.PATCH`; this project is pre-1.0, so `MINOR` bumps may still
change internals.

## [0.3.0] — 2026-10-26

### Added
- **Workbench** (`python -m selfwire.workbench`): local FastAPI server + a
  single-file, offline, responsive neon dashboard. Chat with the agent while
  it creates/reads/updates/deletes files in its own codebase (tests and the
  dashboard UI included), runs pytest with live streamed output, audits
  itself, and commits/rolls back through git. Every change streams to all
  open dashboards over Server-Sent Events. API contract: docs/WORKBENCH_API.md.
- **Test-gated self-improvement loop** (`/improve`, Improve panel): checkpoint
  -> baseline -> plan (one DSPy `ProposeChange` signature) -> pre-check ->
  apply -> full suite + audit -> commit or roll back, with each rejection's
  exact failures fed into the next attempt.
- **Moat** (`workbench/moat.py`, read-only from the workbench): green (or
  strictly less red), no drop in collected/passing tests or in assertions
  under tests/, no rise in skips or high-severity findings, no deleting
  tests, and the test harness (gate modules, every conftest.py, pytest
  config) is read-only to the agent and the loop.
- **Commit gate for the chat agent**: `git_commit` refused unless the latest
  full test run passed after the agent's last edit.
- **Auditor**: syntax/import errors, failing tests, placeholder comments
  (tokenize-based, no string-literal false positives), NotImplementedError,
  untested modules, bare excepts, long functions/files -> score + plan. File
  scans fan out with `osiiso.tmap`.
- **Jobs** on a long-lived `osiiso.ThreadQueue` (infinite mode) with
  per-job timeouts, cancellation, and an exclusive "workspace" group so a
  test run never observes a half-applied change.
- **Skills**: `skills/<name>/SKILL.md`, listed in the agent's context every
  turn and editable by the agent; ships `self-improve` and `codebase-crud`.
- Token auth (constant-time), loopback-by-default binding, refusal to bind
  publicly without a token, restart that first proves new code imports.
- 117 new tests (208 total) including a real-process server e2e (SSE,
  restart re-exec, auth) and regression tests for every moat bypass below.

### Fixed
- `mcp>=1.27.0` had no upper bound; a fresh install pulled mcp 2.x, which
  renamed FastMCP and broke `own_server.py` on import. Pinned `<2`.
- Stale bytecode could make broken code test green: a same-length edit
  within the same second as an earlier import ran the old `.pyc`. Test runs
  and import checks now use an empty per-run `PYTHONPYCACHEPREFIX`.
- Moat bypasses found by attacking the gate before release: planting a
  `conftest.py` hook that reports failures as passes, deselecting tests via
  pytest config, and gutting a test's assertions to `pass` all previously
  passed every rule; all three are now rejected (tests reproduce each).
- Hardening from an independent pre-release review: JUnit counts are
  cross-checked against pytest's own summary; added code is scanned for
  gaming constructs; PYTEST_ADDOPTS/PYTEST_PLUGINS are scrubbed; every pytest
  config file and the whole workbench package (minus its UI) are harness;
  `.git` hooks/config and interpreter startup files are snapshotted and
  restored around each test run (tampering rejects the run); git runs with
  `core.hooksPath=/dev/null`; Host/Origin guard against DNS rebinding;
  token generated by default and kept out of argv on restart; exec and
  MCP-launch levers off in the workbench unless enabled; dashboard edits
  render at `/preview` under a no-network CSP until a restart adopts them;
  an improvement that doesn't commit unwinds its checkpoint; path checks
  are case-insensitive.

### Changed
- Requires **Python 3.13+** (osiiso). Docker image on `python:3.13-slim`;
  compose adds a `workbench` service (bind-mounted repo, your uid,
  loopback-only port, token required) alongside `mcp` and `redis`.
- `.venv/`, `venv/`, `node_modules/` added to `.gitignore`; the workbench
  also writes local git excludes so `add -A` can never commit `.venv`/`.env`
  in any served repo.

## [0.2.0] — 2026-09-28

### Added
- **`SelfWireAgent.aforward()` / `SelfWireAgent.arun()`** — a genuine async
  twin of the existing sync loop, not a thread-wrapped sync call:
  - the reasoning step calls `self.cognize.acall(...)`
    (`dspy.Predict.aforward`, a real `await adapter.acall(...)` against the
    LM client);
  - action execution still runs through the same synchronous `_execute()`
    (which already knows how to safely reach an MCP tool's session on
    `mcp_hub`'s dedicated event-loop thread), but is offloaded via
    `asyncio.to_thread` so a slow tool call can't block the calling
    coroutine's event loop;
  - `arun()` goes through `dspy.Module.acall` (not `aforward` directly), the
    async counterpart of `run()` going through `__call__`, so dspy's own
    call bookkeeping (`caller_modules` tracking, usage tracking) still runs.
  - Concurrency note carried over from the docstring: this makes one
    in-flight run non-blocking for its caller's event loop. It does **not**
    make `ToolGraph` safe against two runs (`aforward`/`aforward` or
    `aforward`/`forward`) against the *same* agent instance concurrently —
    `ToolRegistry` has its own lock, `ToolGraph`'s in-memory mutations do
    not. Run concurrent tasks against separate `bootstrap()`-ed agents.
- **Per-run LM scoping via `dspy.context(lm=...)`** — both `forward()` and
  `aforward()` accept an optional `lm=` kwarg and scope it through
  `dspy.context(**{"lm": lm})` (a shared `_lm_context()` helper; an omitted
  `lm` produces the inert no-op `dspy.context()`, so there's one code path
  either way) instead of requiring a prior global
  `dspy.settings.configure(lm=...)`. One process can now run the agent
  against different models/configs concurrently without them clobbering
  each other's global settings.

### Notes
- No breaking changes to the sync surface (`forward()` / `run()`); the
  async methods are additive.

## [0.1.0] — initial barebones scaffold

- **`registry`** — the live, mutable, thread-safe tool catalog.
- **`exec_tool`** — python `exec` (best-effort `_static_guard`, not a
  sandbox) to compile and register a brand-new tool from source at runtime.
- **`mcp_hub`** — attach to external MCP servers over stdio and pull their
  tools into the registry.
- **`own_server`** — the agent's own growable FastMCP server, mirroring
  everything acquired via the other levers, with meta-tools so growth can
  happen over MCP itself.
- **`agent.py`** — one dual-process DSPy signature (`left_brain` /
  `right_brain` / `synthesis`, each a stacked Pydantic `BaseModel`) driving
  a hand-rolled reasoning loop (not `dspy.ReAct`).
- **`graph_store`** — Hebbian-weighted 3D tool graph + Q-table.
- **`storage`** — Redis-backed persistence (RedisJSON → raw Redis → on-disk
  JSON fallback chain; `raptor-redis`/`graph-redis` don't exist on PyPI, so
  this implements that role directly rather than importing something
  fictional).
- **`telemetry`** — opt-in, pre-probed Phoenix/OTel tracing + dual
  pre-/post-task JSON lifecycle log.
- **`reporter`** — README execution log + timestamped HTML context reports.
- **`graph_viz`** — self-contained neon dark-mode 3D tool-graph viewer.
- 91 tests (unit, a real MCP subprocess round trip, fault injection),
  `demo.py` runnable end-to-end with zero credentials, Docker + Compose
  (selfwire + redis, optional `telemetry` profile for Phoenix).
